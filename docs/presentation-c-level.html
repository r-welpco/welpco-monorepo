Project overview

What is Welpco?

Welpco is a platform that connects customers with Welpers — service providers who offer local, bookable services. Customers search, view profiles, and book; Welpers manage offerings, availability, and bookings.

Current state

  • Single monorepo: backend (BFF), web app, design system, shared packages
  • End-to-end flows implemented: auth, search, profiles, booking lifecycle
  • Simplified architecture: one backend, one database, no Kafka/Redis/OpenSearch

Architecture

Single backend (BFF) with domain modules; frontend talks only to this API.

# Monorepo welpco-monorepo/ ├── apps/bff → NestJS backend (port 3000) — all domain logic in-process ├── apps/web → Next.js 16 frontend (port 8080) ├── apps/design-system → Storybook UI component library └── packages/ → ui, types, database, auth, events, shared Frontend (Next.js) → BFF (NestJS) → PostgreSQL ↓ Geocoding: Google Maps API

No microservices, no message queues. Cache is in-memory; search uses PostgreSQL full-text + pg_trgm.

Backend — domain modules

User & auth

  • Auth: login, register, verify email, reset password, refresh token
  • Users: current user, update
  • Referrals, guardians, admin (e.g. background check)

Profiles & discovery

  • Profiles: onboarding, services/offerings, availability
  • Service discovery: full-text + pg_trgm search
  • Content: categories, service questions, static content

Booking & ops

  • Booking: create, list, detail, accept, decline, cancel, check-in, check-out
  • State machine for booking lifecycle

Supporting

  • Geocode: Google Maps Geocoding API (rate-limited)
  • Notifications: preferences, list
  • Health check

What was developed — frontend

Web app (Next.js 16, React 19)

  • Auth: login, register (customer / Welper), forgot password, reset password, email verification, onboarding
  • Dashboard: search, welper profile (view in dialog), book-now wizard (service questions → confirm), bookings list & detail, profile, settings
  • Notifications: notification center, list, preferences (in-app)
  • Public: search page, welper public profile page
  • PWA: install prompt, offline fallback, service worker (Serwist)

Design system (Storybook)

  • Shared components: typography, layout, forms, platform-specific (service discovery, booking, notifications, payments, reviews, etc.)

Technology stack

Frontend — Next.js 16, React 19, TypeScript Backend — NestJS 11, TypeORM, TypeScript Database — PostgreSQL 16.6 Search — PostgreSQL full-text + pg_trgm Auth — JWT (Passport) + NextAuth.js v5 UI — Radix UI Themes, TanStack Query, Zustand Monorepo — Turborepo, pnpm workspaces Infrastructure — AWS CDK (RDS placeholder)

API docs: Swagger at /api/docs. Test accounts: customer@welpco.com / welper@welpco.com (see README for passwords).

Suggested demo flow

  1. Landing / search (public or logged-in)
  2. Login as customer → Dashboard → Search Welpers
  3. View profile (dialog) → Book now → Wizard (questions + confirm)
  4. Bookings list & booking detail (status, actions)
  5. Optional: login as Welper → Profile, availability, incoming bookings
  6. Optional: PWA install prompt (if on supported device)

Local: Frontend http://localhost:8080 — Backend http://localhost:3000 — Swagger http://localhost:3000/api/docs

Next steps

Domain focus

Several domains are still missing or only partially covered. Priority areas:

  • Real-time messaging — No messaging domain yet; needed for customer–Welper conversation (design system has chat/conversation UI; backend domain to add).
  • Other domains to consider: payments, reviews & ratings, dispute resolution (aligned with design-system capabilities).

Other

  • Booking: availability check at create, timezone handling, conflict handling (transactions / locking).
  • Content & search: expand categories, refine search relevance.
  • Infrastructure: staging deployment, AWS CDK (RDS, compute), monitoring & runbooks.
